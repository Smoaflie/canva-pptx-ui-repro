> Extract a Canva-exported PowerPoint deck into a browser-ready UI manifest and reusable assets for faithful web reconstruction.

Canva PPTX UI Repro is a Codex skill and extraction toolkit for UI implementation work that starts from a Canva design. It reads a `.pptx` export, extracts one slide, and writes a compact `manifest.json` plus copied image/font assets that downstream agents or renderers can consume directly.

Languages: [English](README.md) | [简体中文](README.zh-CN.md)

> [!WARNING]
> This project was generated by AI and has not been manually optimized. It may increase token consumption during agent workflows. Review the implementation and use it with care.

## Features

- **PPTX-to-manifest extraction** - Converts one Canva-exported slide into structured JSON.
- **Browser-ready coordinates** - Emits layout boxes in `browserPixels` with page output dimensions.
- **Asset extraction** - Copies referenced images, SVGs, raster media, and usable embedded fonts.
- **Text normalization** - Preserves text runs, font sizes, letter spacing, paragraph spacing, insets, and render hints.
- **Shape support** - Captures preset geometry, custom SVG path data, fills, strokes, crop data, and transform flips.
- **Agent-friendly contract** - Keeps `manifest.json` as the default reconstruction contract without raw OOXML debug output.

## Requirements

- Python 3.8 or newer
- A Canva-exported `.pptx` file
- Optional: a reference `.png` export for validation metadata

The extractor uses only the Python standard library.

## Installation

Clone or copy this repository, then run the extractor directly with Python:

```powershell
cd .\canva-pptx-ui-repro
python .\scripts\extract_pptx_manifest.py --help
```

No package installation step is required for the current extractor.

## Install as a Codex Skill

This repository is a Codex skill directory because it contains `SKILL.md` at the repository root. Install it by placing the whole directory under `$CODEX_HOME/skills`.

From the parent directory of this repository:

```powershell
$skillsRoot = if ($env:CODEX_HOME) { Join-Path $env:CODEX_HOME "skills" } else { Join-Path $HOME ".codex\skills" }
$dest = Join-Path $skillsRoot "canva-pptx-ui-repro"
New-Item -ItemType Directory -Force -Path $skillsRoot | Out-Null
New-Item -ItemType Directory -Force -Path $dest | Out-Null
Get-ChildItem -Path .\canva-pptx-ui-repro -Force | Copy-Item -Destination $dest -Recurse -Force
```

Restart Codex after installation so the new skill is discovered. You can then ask Codex to use `$canva-ui-implementation` or reference the installed skill by its `SKILL.md` name, `canva-ui-implementation`.

## Usage

### Extract a specific slide

`--slide-index` is 1-based.

```powershell
python .\scripts\extract_pptx_manifest.py .\work\input\deck.pptx `
  --output-dir .\work\slide-2 `
  --slide-index 2
```

### Add optional PNG validation metadata

The optional reference PNG is used for metadata and mismatch warnings. It does not rescale the extracted layout.

```powershell
python .\scripts\extract_pptx_manifest.py .\work\input\design.pptx `
  --output-dir .\work\extracted `
  --slide-index 1 `
  --reference-png .\work\input\design.png
```

### Consume the manifest in UI work

Before writing a renderer or implementation code, read:

- [Manifest Schema](references/manifest-schema.md)
- [Manifest Normalization Rules](references/manifest-normalization-rules.md)

The normal reconstruction path should consume only `manifest.json`:

- `page.outputWidth` and `page.outputHeight` define the target canvas.
- Element `x`, `y`, `width`, `height`, `rotation`, `zIndex`, and `transform` drive placement.
- `fills`, `strokes.widthPx`, `geometry`, `image.source`, `fills.browserCrop`, and `fonts` drive rendering.
- Text renderers should use normalized `fontSizePx`, `letterSpacingPx`, paragraph spacing `cssPx`, and `text.renderHints` when present.

## Manifest Output

`manifest.json` has this top-level shape:

```json
{
  "summary": {},
  "page": {},
  "fonts": [],
  "assets": [],
  "elements": []
}
```

Use `summary` first to inspect the output size, element counts, asset count, font count, and warnings before expanding the full element tree.

## Workflow Guidance

This repository is designed for two UI implementation modes:

- **Reconstruction** - Extract a Canva PPTX slide, then rebuild the same screen from the manifest.
- **Adaptation** - Inspect an existing UI and use the extracted manifest as evidence for spacing, assets, typography, and layout decisions.

For reconstruction, the PPTX-derived manifest is the layout contract. If a browser-ready field is missing, report the missing field and fidelity risk before inventing fallback logic.

## Development Notes

- The extractor intentionally avoids producing `manifest.raw.json` in the default workflow.
- Raw OOXML provenance should only be generated through an explicit debug path if one is added later.
- Existing scripts are small modules split by concern: package IO, layout model, style parsing, shape parsing, and CLI orchestration.
